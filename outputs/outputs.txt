The outputs/ directory serves as the centralized artifact repository for all analytical, statistical, and publication-ready assets generated by the platform.
Unlike the logs/ directory (which contains raw, rolling runtime text logs) or the checkpoints/ directory (which stores binary AI model weights), the outputs/ folder contains the derived insights, visualizations, and statistical reports produced by the training, evaluation, and interpretability pipelines.
(Note: Like checkpoints/ and logs/, the outputs/ directory is strictly gitignored. It contains generated artifacts, not source code.)
Here is the exact structure of the outputs/ folder and the information contained within each file.

2. Detailed Breakdown of File Contents

A. The paper/ Directory (Executive & Academic Assets)
This folder contains the final, polished assets meant for external consumption (whitepapers, presentations, stakeholder reports).
- .png / .pdf Figures: High-resolution (300 DPI) images generated by generate_paper_figures.py. They use consistent color palettes, typography, and formatting.
- results_table.tex: A pre-formatted LaTeX table containing the final ablation results. This allows researchers to copy-paste the table directly into an Overleaf document without manually formatting columns.
- manifest.json: A machine-readable index of everything in the folder. It contains the generation timestamp, file sizes, and SHA-256 hashes of the images to ensure no one tampered with the published figures.

B. The ablation/ and three_way/ Directories (Statistical Rigor)
These folders contain the raw data and statistical proofs that validate the AI's performance.
- raw_results.csv: A comma-separated file containing the exact metrics (Total Carbon, SLA Violations, Reward, Migrations) for every single episode across every random seed. This allows external auditors to re-run statistical tests in R, Python, or Excel.
- statistical_tests.json: The mathematical proof of significance. It contains:
-- t_stat: The t-score from the paired t-test.
-- p_value: The probability that the results occurred by chance (e.g., 0.008).
-- significant: A boolean (true/false) indicating if p< 0.05.
- comparison_summary.json: A quick-reference file for dashboards. It holds the mean, standard deviation, and 95% Confidence Intervals (CI) for each approach, making it easy for a web UI to display "Window=5 reduces carbon by 16.6% ± 2.1%".

C. The interpretability/ Directory (Model Explainability)
This is the most complex folder, containing the outputs of the LSTMInterpreter toolkit. It proves why the AI made its decisions.
- tsne_clustering.png: A 2D scatter plot showing how the LSTM's internal memory groups "Clean Grid" hours vs. "Dirty Grid" hours.
- temporal_attribution.png: A heatmap showing which historical hours (e.g., t−1, t−2) had the highest influence on the agent's final decision.
- linear_probe_results.json: Contains the R^2  scores proving the LSTM is implicitly forecasting. For example:
json
{
  "horizon_0h": { "mean_r2": 0.85 },
  "horizon_1h": { "mean_r2": 0.48 },
  "horizon_3h": { "mean_r2": 0.22 }

}
- interpretability_report.json: A comprehensive, nested JSON file containing all numerical metrics, silhouette scores, and confidence-reward correlations generated during the analysis.

3. How These Files are Managed in the Lifecycle
a) Generation: The files are not written manually. They are generated deterministically by running specific scripts:
- python scripts/generate_paper_figures.py populates outputs/paper/.
- python -m src.training.statistical_ablation populates outputs/ablation/.
- python -m src.interpretability.run_interpretability populates outputs/interpretability/.
b) Versioning: Because the outputs/ folder is gitignored, it is not tracked by Git. However, the scripts that generate them are tracked. If an executive asks, "How was Figure 4 generated?", you can point to the version-controlled generate_paper_figures.py script and the raw_results.csv to prove the figure is reproducible.
c) Archival: For long-term storage, the outputs/ folder (specifically the paper/ and ablation/ subfolders) should be zipped and uploaded to cloud object storage (like AWS S3) alongside the checkpoints/ folder at the end of every major experiment or quarterly retraining cycle.

Summary
The outputs/ folder is the evidence locker of the Carbon-Aware Deep Reinforcement Learning Platform. While the src/ folder contains the logic and the checkpoints/ folder contains the intelligence, the outputs/ folder contains the proof—the mathematical, visual, and statistical evidence that the system works safely, effectively, and transparently.
